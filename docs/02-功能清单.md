## 〇、产品定位（用户明确修正）

**一句话**：**Codeway**是面向日常同路出行的拼友匹配平台——用户与用户之间约定同行（结伴），**不是司机接单或车辆调度平台**。

- **市面拼车软件**：乘客 ↔ 司机的约定，重心在“拼到车”。
- **Codeway**：用户 ↔ 用户的约定，重心在“**拼到人**”。
- **共同打车场景**：成团后由发单人选择并跳转第三方打车平台（滴滴/高德/微信打车等）下单；本平台记录拼友约定、车辆信息和费用凭证，不提供叫车或调度。
- **安全边界**：车辆定位与行车监控由第三方打车平台提供；小程序不采集车辆位置、不做自动行车守护，仅提供手动 SOS、紧急联系人、车辆信息同步和费用透明。

**目标群体与场景**：
1. **首个验证场景（MVP）**：校园及周边的学生、教职工、居民等已完成手机号验证的用户；优先验证晚间通勤/返校，但不限于夜间。
2. **扩展场景**：城市内日常通勤、活动散场、跨区域同路出行；按城市/服务区域逐步开放，而非一次性面向全国开放。
3. **身份模型**：所有用户完成手机号验证后才可发布/加入；学生认证为可选的信任标识，不作为社会用户的准入障碍。

### 〇.1 角色与行程状态（v3 新增）

**角色**：普通用户、发单人、拼友、管理员；紧急联系人仅接收 SOS 通知，不登录或参与行程。项目不设司机端。

**主状态**：`招募中 → 双向确认中 → 已成团 → 待叫车 → 已叫车 → 行程结束待结算 → 结算完成 → 待评价 → 已归档`。MVP 单车总人数为 3 或 4（含发单人），允许一次加入 1–2 名拼友；只有全部成员确认后才进入“已成团”。

**例外状态**：`用户取消`、`发单人取消`、`已满员`、`已过期`、`订单有争议`、`管理员下架`。已过出发时间但尚未成团的行程自动过期；已成团行程仅由成员取消或管理员介入终止。

**关键权限**：发单人可发起第三方叫车、录入/修改车辆信息、提交订单；所有成员可查看行程、聊天、确认费用、标记线下已付、取消和举报；管理员可下架、处理举报和争议。费用比重在成团前可修改；成团后锁定，必须通过成员同意的变更申请，申请通过后清空原确认并重新由全部成员确认锁定。

**确认事务与幂等**：每个成员只能存在一条当前确认记录；确认接口必须携带幂等键并在事务内锁定行程行。最后一名成员确认时，后端原子写入“已成团”和反悔截止时间；截止时间内任一成员撤回，事务内将行程回退“招募中”、确认全部作废并发送通知。重复确认、重复撤回和并发请求只能得到同一结果，不得重复成团。

## 一、核心用户流程（拼单闭环 v3）

```
发布行程 → 浏览行程列表（按日期导航）→ 筛选/顺路推荐
  → 进入行程详情 → 发起聊天确认（会合地点/时间/费用比重）
  → 双方双向确认（防误触）→ 拼单成功（列表下架，进入"我的出行"）
  → 发单人跳转第三方打车软件下单（含免责提示；唤起失败时复制路线信息并手动打开 App）
  → 叫车成功：录入车牌/车型，同步展示给全部拼友
  → 行程结束：发单人上传第三方打车订单截图 + 填写实际总车费（同步全部拼友）
  → 全员确认或提出异议 → 微信/支付宝线下转账分摊 → 标记已付 → 互评 → 信誉沉淀
  → 遇到危险：用户手动触发 SOS（本人手机 GPS + 行程基础信息 → 紧急联系人）
```

|---|---|---|---|---|

| G2 | 新行程订阅提醒 | P1 | 微信订阅消息：附近新行程/同路线行程通知 | 订阅后新单到达有推送，频率可控 |
| G3 | **推荐埋点与决策记录** | P0 | 记录行程卡片曝光、点击、发起聊天、双向确认、取消、完成及异常重试；保存推荐理由码、行程 ID、规则版本和生成时间；不记录不必要的精确位置 | 事件字段统一、重复上报可去重；每次推荐可追溯理由码和规则版本；支持后续 P1 调权 |

### H 后台管理

| 编号 | 功能 | 优先级 | 说明 | 验收标准 |
|---|---|---|---|---|
| H1 | 举报与审核 | P0 | 用户可举报（骚扰/爽约/虚假信息/虚报车费），管理员受理、留存证据、处理并通知结果 | 举报提交、证据留存、人工处置和结果通知闭环可走通 |

### 跨页面 P0 体验与可观测性要求

1. 首页、筛选、详情、聊天、我的出行、叫车、车辆、订单、费用、评价、SOS、认证和设置页面均必须定义空状态、加载失败、权限拒绝、网络失败、无结果、已过期和重试操作；禁止出现空白页面。
2. 空状态必须提供与当前任务相关的快捷操作，例如“清除筛选”“回到今天”“重新加载”“发布行程”“复制路线信息”“联系管理员”。
3. 推荐理由仅用于解释匹配依据，不代表平台对用户身份、履约或安全作担保；低信用行程不展示正向推荐文案。
4. 推荐决策日志 P0 保存理由码、规则版本和生成时间；P2 仅新增管理员可视化查询，不新增用户关闭理由入口。

## 五、范围边界（本期明确不做）

1. **不做行车自动守护**——实时位置共享、到家确认、超时预警、地理围栏、位置偏离/静止检测全部移除；车辆定位与行车监控由第三方打车平台提供
2. **不做系统自动派单**——用户自主选择 + 双向确认是产品核心，推荐仅辅助
3. **不做在线支付/资金托管**——费用只确认比重与记录，转账跳转微信/支付宝
4. **不做叫车/调度**——叫车由发单人跳转第三方平台完成
5. **不做陌生人社交/聊天广场**——聊天仅限行程确认场景
6. **不做护送/救援承诺**——SOS 只通知紧急联系人 + 110 报警引导（非自动报警），产品明确免责
7. **不做设备级 GPS 自动检测**——异常行为识别仅靠用户举报/爽约记录人工辅助，无自动监测
8. **不一次性面向全国开放**——MVP 在选定校园及周边服务区域内，向完成手机号验证的学生、教职工和社会用户开放；后续按城市逐步扩展
9. **不做校内权威数据对接**（课表/门禁等）

## 六、隐私与合规（v2 新增）

1. **位置隐私**：非成团状态只展示模糊位置信息（如"3 号宿舍楼附近"）；SOS 仅在用户手动触发时采集本人手机 GPS
2. **数据销毁**：SOS 的临时 GPS 在发送完成后立即销毁；订单截图仅向行程成员和管理员开放，结算完成后保留 90 天作为费用凭证，有争议时延长至争议处理完成后 90 天；截图只接受 PNG/JPEG/WebP，单张不超过 10MB
3. **免责声明**：跳转第三方打车前强制弹出免责提示（车辆定位、行车安全服务由第三方提供，本平台仅提供拼友匹配）
4. **性别信息**：可选授权、非强制；仅用于筛选展示，不强制填写
