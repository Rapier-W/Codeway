## P01 启动/登录页

**用途**：首次进入引导手机号短信验证码登录，老用户通过 HttpOnly Cookie 自动恢复会话。
**信息要素**：
- 产品名 + 一句口号（“找同路人，结伴更安心”）
- 手机号输入框、获取验证码按钮、验证码输入框
- 60 秒倒计时、发送失败和频率限制提示
- 说明：验证码校验成功即完成手机号验证；未登录用户发单/加入时跳转本页
- 隐私协议/用户协议勾选入口

**交互要点**：短信验证码校验成功 → 建立 Cookie 会话并完成手机号验证 → 返回原页面或首页。学生认证为可选信任标签，不拦截发布或加入。

```
┌─────────────────────────┐
│                         │
│        🚕🚕🚕           │
│        同路行             │
│   "找同路人，结伴更安心"  │
│                         │
│  ┌───────────────────┐  │
│  │  获取短信验证码     │  │
│  └───────────────────┘  │
│                         │

```

## P02 首页（行程列表）★ 主界面

**用途**：按日期浏览附近拼车单，选择合适搭档。
**信息要素**：
- 顶部：日期导航栏（横向滑动，默认 7 天）+ "筛选"按钮 + **"回到今天"快捷按钮（P1）**
- 行程卡片：大字 出发地 → 目的地；大字 出发时间；小字 时间浮动/拼车次数/成功率/人数（如 1/3、2/4）；可选标签（学生认证/仅女性）；后端输出的推荐理由最多展示 3 条：时间相近、履约稳定、已认证学生、仍有空位。P1 高德接口上线后再增加路线类标签；低信用行程不展示正向推荐文案。
- 底部导航：首页 / 发布(+) / 我的出行 / 我的

**交互要点**：滑动日期切换列表；**排序 = 出发时间优先，不使用加分项**；下拉刷新。筛选结果也显示同一套理由码。

**首页提示**：在列表上方显示简短提示：“推荐仅根据时间、履约、认证等信息辅助匹配，不代表平台对用户身份、履约或安全作担保。”

**状态补充**：需提供“该日期暂无行程”“当前筛选无结果”“网络异常，点击重试”“行程已满/已过期”状态；每个状态配快捷操作；“附近”按当前选定服务区域和筛选地点解释，未授权定位时仍可手动选点浏览。记录曝光、点击、发起聊天、确认和异常重试埋点。

**用途**：发布拼车单。
**信息要素**：
- 出发地 / 目的地（地图选点）
- 日期 + 出发时间（±15 分钟浮动）
- 人数上限（P0 可选 3 或 4 人，含发布者；一次加入 1–2 名拼友）
- 费用分摊模式：固定均摊 / 按人头固定金额 / 自定义比例（总和 100%）

- 拼车要求/个人诉求（选填）

**用途**：查看单详情并决定是否发起拼车沟通。
**信息要素**：
- 地图（出发地/目的地/近似路线；P0 不展示路线推荐理由；P1 展开完整匹配理由和数据口径）
- 大字：出发地 → 目的地、出发时间（含浮动）

- 发布者信息卡：昵称、认证、拼车次数、成功率、评分
- 拼车要求/个人诉求、性别限制
- 联系电话（授权后展示）
- 费用模式说明
- **成团后：车辆信息卡（车牌/车型，见 C7）**

## P06 聊天窗口页 ★ 拼前确认核心

**用途**：确认会合地点、时间、费用比重；达到目标人数后的全员确认成团（防误触）。
**信息要素**：
- 对方信息头（昵称/认证/信誉）
- 消息区：文字 / 位置 / 快捷短语（在哪汇合/稍等 5 分钟/我已到达）
- 费用确认卡片（含提示文字：「最终实际车费以第三方打车订单为准，以此订单进行协商结算」）
- 成团后费用卡片显示“已锁定”；仅发单人可发起“申请修改”，填写原因和新分摊方案，不能直接修改
- 除申请人外的全部当前活动成员同意变更后，原确认状态清空，全部成员重新确认并再次锁定；任一成员拒绝或 24 小时未响应则申请失效
- 全员确认按钮：达到目标人数后，全部当前活动成员点击二次确认；最后一人确认后提供 15 秒反悔。窗口内任一成员撤回确认时，显示“已回到招募中”，全部确认作废、非发单人席位释放并通知受影响成员；确认卡显示“已确认 n/目标人数”、未确认成员和倒计时
- 通话按钮
- 成团后：通知卡片 + "去叫车"入口

## P11 订单共享页（新增）★ 费用透明核心

**用途**：行程结束后由发单人提交第三方订单，成员查看并确认或提出异议，作为费用分摊依据。
**信息要素**：
- 行程摘要
- 上传打车订单截图（图片）
- 实际总车费（数字填写）
- 同步状态：待 N 位拼友确认 / 已确认 / 有异议

## 全局空状态、异常与埋点规范（P0）

所有页面禁止出现空白页，至少覆盖以下状态，并提供快捷操作：

| 状态 | 示例提示 | 快捷操作 |
|---|---|---|
| 无数据 | “今天还没有同路行程” | 发布行程 / 切换日期 |
| 筛选无结果 | “没有符合条件的行程” | 清除筛选 / 修改时间 |
| 权限拒绝 | “未授权位置，仍可手动选择地点” | 手动选点 / 去设置 |
| 网络失败 | “加载失败，请重试” | 重新加载 |

| 订单有争议 | “费用暂被冻结，处理完成后继续” | 查看争议 / 联系管理员 |
| 第三方唤起失败 | “已复制路线信息，请手动打开打车 App” | 复制路线 / 打开第三方 App |

P0 埋点至少包括：卡片曝光、卡片点击、推荐理由展示、发起聊天、费用确认、全员确认、15 秒反悔、取消、订单提交、确认/异议、完成和异常重试。推荐决策记录包含理由码、规则版本、行程 ID、生成时间，不记录不必要的精确位置。

## Web/PWA 交互基线（v4）

- 前端技术：Vue 3 + Vite + TypeScript + Vant + Pinia。
- 桌面端使用响应式两栏/三栏布局，移动端保持底部导航和底部操作栏；不再依赖小程序原生导航。
- PWA Service Worker 只缓存静态构建资源；接口、聊天、订单截图、手机号和 SOS 数据全部 `no-store`。
- 登录会话由 HttpOnly Cookie 管理，Pinia 只保存当前用户展示信息，不保存 token。
- 网络失败、权限拒绝、空列表、过期和争议锁定必须使用统一空状态/错误提示组件，并提供重试、清除筛选、复制路线或联系管理员操作。

## 响应式与移动端交互规范（正式版，P0）

本节是网站/PWA 的强制交互基线。任何新增页面或组件都必须同时通过手机窄屏、软键盘、弱网和安全区检查；桌面端适配不能牺牲手机端可操作性。

### 1. 视口、断点与布局

- **布局断点**：320–767px 使用单列手机布局；768–1023px 使用平板布局；≥1024px 可使用两栏/三栏，但核心业务列最大宽度 720px，不能把手机卡片无限拉伸。
- **触控与溢出**：所有可点击控件最小触控目标 `44×44px`，主操作按钮最小高度 `48px`；不依赖 hover 才能完成操作；页面、卡片、图片和地图禁止横向滚动或溢出。
- **安全区与视口**：底部导航、固定操作栏和聊天输入区必须使用 `env(safe-area-inset-bottom)`；全高视图使用 `100dvh`，不能被 iOS Home Indicator 或移动浏览器地址栏遮挡。
- **输入与弹层**：手机号使用数字键盘，验证码支持系统一次性验证码自动填充；输入聚焦时必须避让软键盘，提交/发送按钮始终可见。移动端弹层采用底部抽屉或全屏页，并处理返回、ESC、焦点锁定和背景滚动锁定。
- **地图、图片与弱网**：定位拒绝、高德 SDK 初始化失败或弱网时保留可触摸/键盘操作的手动模糊地点输入；订单截图预览受控缩放且不出视口。PWA 不缓存订单截图、聊天、手机号或 SOS 数据。
- **浏览器能力降级**：第三方叫车、转账和浏览器推送先检测能力再尝试；失败、拒绝授权或浏览器不支持时必须提供复制信息、手动打开 App 或明确不可用说明。浏览器推送不得用于 P0 关键状态通知。

### 2. 移动端交互状态

- **加载**：首屏、列表翻页、提交和聊天发送均显示局部骨架或按钮 loading；请求进行中禁止重复提交，但允许取消可取消的查询。
- **空状态**：每个空场景必须说明原因并给出单一主操作：清除筛选、重新加载、去发布行程或返回首页；禁止只显示空白区域。
- **错误与恢复**：错误提示靠近触发控件，保留用户已填写内容；网络失败提供“重试”，鉴权过期引导重新登录，容量/状态冲突提示最新状态并刷新详情。
- **确认与危险操作**：接受、确认成团、费用变更、举报和 SOS 均采用明确的二次确认；15 秒反悔窗口使用页面顶部倒计时和固定操作栏，不依赖 Toast 承载关键状态。
- **底部操作栏**：移动端主操作固定在底部安全区内，内容滚动区域预留等高 padding；键盘出现时操作栏随视觉视口上移，不能遮挡输入框或发送按钮。

### 3. 触控、键盘与可访问性

- 所有业务动作支持触控和键盘 Enter/Space；焦点顺序与视觉顺序一致，弹层打开后焦点锁定在弹层内，关闭后回到触发控件。
- 文本、状态标签和推荐理由必须支持系统字体放大；不以颜色作为唯一状态表达，并提供 aria-label/可读文本。
- 手势仅作为快捷方式，不能替代可见按钮；横向滑动卡片、地图拖拽和图片缩放必须有键盘/按钮替代路径。

### 4. 验收矩阵

开发自测至少覆盖：320px、375px、414px 手机宽度；横竖屏切换；iOS/Android 软键盘；底部安全区；弱网/断网；无定位权限；地图或第三方叫车能力不可用；PWA 离线打开静态壳。敏感接口、聊天、订单截图、手机号和 SOS 数据必须 `no-store`，不得进入 Service Worker 缓存。
