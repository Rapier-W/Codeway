## P01 启动/登录页

**用途**：首次进入引导微信登录与手机号验证，老用户自动登录。
**信息要素**：
- 产品名 + 一句口号（“找同路人，结伴更安心”）
- 微信一键登录按钮（静默授权）
- 未验证提示条："手机号验证后才能发布/加入行程"
- 隐私协议/用户协议勾选入口

**交互要点**：登录成功 → 检查手机号验证状态 → 未验证弹引导（可跳过，仅浏览）。学生认证为可选信任标签，不拦截发布或加入。

```

│        🚕🚕🚕           │
│        Codeway             │
│   "找同路人，结伴更安心"  │
```

## P02 首页（行程列表）★ 主界面

**用途**：按日期浏览附近拼车单，选择合适搭档。
**信息要素**：
- 顶部：日期导航栏（横向滑动，默认 7 天）+ "筛选"按钮 + **"回到今天"快捷按钮（P1）**
- 行程卡片：大字 出发地 → 目的地；大字 出发时间；小字 时间浮动/拼车次数/成功率/人数（如 1/3、2/4）；可选标签（学生认证/仅女性）；后端输出的推荐理由最多展示 3 条：时间相近、履约稳定、已验证、仍有空位。P1 高德接口上线后再增加路线类标签；低信用行程不展示正向推荐文案。
- 底部导航：首页 / 发布(+) / 我的出行 / 我的

**交互要点**：滑动日期切换列表；**排序 = 出发时间优先，不使用加分项**；下拉刷新。筛选结果也显示同一套理由码。

**首页提示**：在列表上方显示简短提示：“推荐仅根据时间、履约、认证等信息辅助匹配，不代表平台对用户身份、履约或安全作担保。”

**状态补充**：需提供“该日期暂无行程”“当前筛选无结果”“网络异常，点击重试”“行程已满/已过期”状态；每个状态配快捷操作；“附近”按当前选定服务区域和筛选地点解释，未授权定位时仍可手动选点浏览。记录曝光、点击、发起聊天、确认和异常重试埋点。

## P04 发布行程页

**用途**：发布拼车单。
**信息要素**：
- 出发地 / 目的地（地图选点）
- 日期 + 出发时间（±15 分钟浮动）
- 人数上限（P0 可选 3 或 4 人，含发布者；一次加入 1–2 名拼友）
- 费用分摊模式：固定均摊 / 按人头固定金额 / 自定义比例（总和 100%）
- **仅接受女性拼友（勾选，可选）**
- 拼车要求/个人诉求（选填）
- 备注（选填）
- 地图路线预览

## P05 行程详情页

**用途**：查看单详情并决定是否发起拼车沟通。
**信息要素**：
- 地图（出发地/目的地/近似路线；P0 不展示路线推荐理由；P1 展开完整匹配理由和数据口径）
- 大字：出发地 → 目的地、出发时间（含浮动）
- 人数：当前人数/总人数（如 1/3、2/4）
- 发布者信息卡：昵称、认证、拼车次数、成功率、评分
- 拼车要求/个人诉求、性别限制
- 联系电话（授权后展示）
- 费用模式说明
- **成团后：车辆信息卡（车牌/车型，见 C7）**
- **成团后：订单共享状态（见 F2）**
- 匹配理由折叠区（P1）：时间相近、履约稳定、已验证、仍有空位；点击后显示计算口径和生成时间
- 底部按钮：[发起拼车沟通]；不可加入时显示原因（未验证、已满、性别限制、时间冲突、行程已过期）

## P06 聊天窗口页 ★ 拼前确认核心

**用途**：确认会合地点、时间、费用比重；双向确认成团（防误触）。
**信息要素**：
- 对方信息头（昵称/认证/信誉）
- 消息区：文字 / 位置 / 快捷短语（在哪汇合/稍等 5 分钟/我已到达）
- 费用确认卡片（含提示文字：「最终实际车费以第三方打车订单为准，以此订单进行协商结算」）
- 成团后费用卡片显示“已锁定”；仅发单人可发起“申请修改”，填写原因和新分摊方案，不能直接修改
- 拼友同意变更后，原确认状态清空，双方重新确认并再次锁定
- 双向确认按钮：点击后二次确认弹窗，确认后提供 15 秒反悔；反悔窗口内任一方取消时，显示“已回到招募中”，双方收到通知
- 通话按钮
- 成团后：通知卡片 + "去叫车"入口

**信息要素**：
- **Tab 拆分：我发布的 / 我加入的（P0）**

## P08 SOS 确认弹层（保留）

**用途**：手动 SOS 防误触确认。
**信息要素**：
- 警告文案："将向紧急联系人发送**你的手机位置**与行程基础信息"
- 可选：显示 110 报警引导（P1，非自动拨号）
- 取消 / 确认发送

**交互要点**：长按 3 秒触发 → 确认发送 → 发送本人 GPS（若获取成功）+ 行程信息；冷却 5 分钟。位置未授权/获取失败时仍可发送行程信息，并显示“未附位置”；展示发送中、成功、失败和冷却中状态。**无自动触发。**

```
┌─────────────────────────┐
│  ⚠ 发送紧急求助？        │
│  将向 3 位紧急联系人发送   │
│  你的手机位置和行程信息。  │
│  ☐ 同时显示报警引导(110)  │
│                         │
│   [取消]    [确认发送]    │

```

- 行程摘要
- 上传打车订单截图（图片）
- 实际总车费（数字填写）
- 同步状态：待 N 位拼友确认 / 已确认 / 有异议

## 全局空状态、异常与埋点规范（P0）

所有页面禁止出现空白页，至少覆盖以下状态，并提供快捷操作：

| 状态 | 示例提示 | 快捷操作 |
|---|---|---|
| 无数据 | “今天还没有Codeway程” | 发布行程 / 切换日期 |
| 筛选无结果 | “没有符合条件的行程” | 清除筛选 / 修改时间 |
| 权限拒绝 | “未授权位置，仍可手动选择地点” | 手动选点 / 去设置 |
| 网络失败 | “加载失败，请重试” | 重新加载 |
| 行程已过期/已满 | “该行程已结束招募” | 返回列表 |
| 订单有争议 | “费用暂被冻结，处理完成后继续” | 查看争议 / 联系管理员 |
| 第三方唤起失败 | “已复制路线信息，请手动打开打车 App” | 复制路线 / 打开第三方 App |

P0 埋点至少包括：卡片曝光、卡片点击、推荐理由展示、发起聊天、费用确认、双向确认、15 秒反悔、取消、订单提交、确认/异议、完成和异常重试。推荐决策记录包含理由码、规则版本、行程 ID、生成时间，不记录不必要的精确位置。

学生认证只作为标签和排序依据，不触发布局外的强认证弹窗，不阻拦发布或加入。
