# 07 - 同路行系统架构方案（当前确认基线）

> 文档版本：v4.1（网站/PWA 基线）
> 更新日期：2026-08-24
> 文档性质：当前已确认的架构基线，不等同于最终技术实施方案。  
> 关联文档：`02-功能清单.md`、`03-页面设计.md`、`04-竞品调研.md`、`05-重点模块方案.md`、`06-文档审查与修改建议.md`

## 一、架构决策摘要

当前已经确定：

1. 客户端采用**手机优先的响应式 Web/PWA**，兼容桌面浏览器。
2. 后端采用**独立后端服务**，不把核心业务逻辑锁定在微信云开发中。
3. 核心业务数据库采用**PostgreSQL**。
4. 后端部署在**七牛云云服务器 VM**，入口地址由七牛云 VM 对外提供服务。
5. 第三方打车跳转采用**适配器 + 手动降级**模式，不能假设所有平台都支持直接唤起。
6. 订单截图、认证材料等文件不属于数据库字段，采用七牛云 Kodo 私有对象存储；数据库只保存对象键和访问元数据。

整体原则：Vue PWA 负责页面交互和浏览器能力，独立后端负责业务状态、权限、费用、推荐、审计和安全规则；外部平台通过适配器接入，避免业务层直接依赖某一个供应商。

## 二、产品范围对架构的约束

同路行是用户与用户之间的同路匹配平台，不是司机接单或车辆调度平台。

MVP 首个验证范围：

- 选定校园及周边服务区域；
- 学生、教职工和社会用户均可使用；
- 所有发布/加入用户完成手机号验证；
- MVP 单车总人数为 3 或 4（含发单人），一次加入 1–2 名拼友；
- 优先验证晚间通勤/返校，但产品不限于夜间。

MVP 必须支持：

- 行程发布、列表、筛选和推荐理由；
- 行程绑定聊天；
- 达到目标人数后的全员确认和 15 秒反悔窗口；
- 第三方叫车跳转及失败降级；
- 车辆信息同步；
- 订单截图共享、费用确认和争议锁定；
- 手动 SOS、紧急联系人和举报；
- 评价、取消记录、埋点和推荐决策日志。

明确不做：

- 司机端和车辆调度；
- 平台内车辆实时定位；
- 自动行车守护、自动地理围栏和自动异常检测；
- 在线支付、钱包和资金托管；
- 陌生人聊天广场。

## 三、逻辑架构

```text
┌─────────────────────────────────────────────┐
│            Vue 3 + Vite + PWA 客户端          │
│ 短信登录 │ 行程 │ 聊天 │ 确认 │ 订单 │ SOS │
└──────────────────────┬──────────────────────┘
                       │ HTTPS / WebSocket
                       ▼
┌─────────────────────────────────────────────┐
│              独立后端 API 服务                │
│ 认证与用户 │ 行程状态机 │ 匹配推荐 │ 聊天     │
│ 费用争议   │ 车辆订单   │ SOS事件 │ 评价举报 │
│ 埋点审计   │ 管理员接口 │ 外部服务适配器     │
└───────┬───────────┬───────────┬─────────────┘
        │           │           │
        ▼           ▼           ▼
  PostgreSQL    对象存储       外部平台
  业务数据      订单截图       高德/短信/叫车/
  状态/审计     认证材料       第三方打车平台
```

### 3.1 Web/PWA 客户端职责

- 展示行程列表、卡片理由、详情和空状态；
- 发起聊天、全员确认、取消和费用变更申请；
- 调用手机号短信验证码登录、浏览器位置权限和 PWA 能力；
- 选择第三方打车平台并执行可用的 Web/App 跳转；
- 在跳转失败时复制路线信息并引导用户手动打开第三方 App；
- 上传订单截图并展示订单/费用/争议状态；
- 展示 SOS 触发过程，不自行判断安全事件。

客户端不直接决定核心业务状态，不在客户端计算最终费用，不在客户端保存可信的信用或权限结果。PWA 只缓存静态资源，不缓存聊天、订单截图、手机号或 SOS 数据。

### 3.2 独立后端职责

- 通过七牛云短信验证码建立手机号会话；使用 HttpOnly、Secure、SameSite=Lax Cookie，refresh token 只保存哈希并支持撤销；
- 管理用户、行程、成员、聊天、确认、取消和评价；
- 执行行程状态机和费用状态机；
- 生成最多 3 条固定推荐理由码，不在 MVP 进行加分排序；
- 保存推荐决策日志和曝光/点击/确认等埋点；
- 管理订单截图访问权限、订单确认、异议和费用锁定；
- 处理 SOS 事件审计、举报、管理员操作和审计记录；P0 不负责自动通知联系人或自动报警；
- 通过适配器调用地图、消息、短信、对象存储和第三方打车能力。

## 四、部署架构

### 4.1 当前确认部署

```text
用户浏览器 / PWA
        │ HTTPS / WSS
        ▼
七牛云 VM
  ├─ 反向代理（HTTPS）
  ├─ 独立后端 API
  ├─ WebSocket 服务
  └─ 定时任务/健康检查
        │
        ├─ PostgreSQL（生产部署方式待定；本地使用 Docker）
        ├─ 七牛云 Kodo（已确定，私有桶）
        └─ Redis（MVP 可选）
```

### 4.2 七牛云 VM 的定位

七牛云 VM 负责运行同路行的独立后端服务，不负责替代业务数据库和文件存储的逻辑边界。管理入口：[七牛云云服务器 VM](https://portal.qiniu.com/las/vm/instances)。

VM 至少需要：

- 固定公网访问能力或稳定域名解析；
- HTTPS 证书；
- 防火墙和安全组；
- 后端进程守护与自动重启；
- CPU、内存、磁盘和网络监控；
- 日志留存与异常告警；
- 数据库和配置文件备份策略。

订单截图不建议仅保存在 VM 本地磁盘，避免实例故障、磁盘损坏或迁移导致凭证丢失。

### 4.3 单 VM MVP 数据库部署

PostgreSQL 已确定为数据库类型。MVP 先与 API 同在一台七牛云 VM，由 Docker Compose 运行；PostgreSQL 仅加入 Docker 内部网络，不开放公网。每日执行 pg_dump 并加密上传 Kodo。用户规模扩大或高可用要求提高后，再迁移到独立/托管 PostgreSQL。

## 五、核心数据边界

### 5.1 PostgreSQL 保存

- 用户、手机号验证、可选学生认证和性别授权状态；
- 服务区域、地点模糊信息和行程；
- 加入申请（1–2 席）、活动成员、容量占用、全员确认、15 秒反悔、取消和爽约记录；
- 聊天消息和结构化确认卡片；
- 费用模式、比例、变更申请、成员同意和重新锁定记录；
- 车辆信息、订单元数据、订单确认/异议状态；
- 评价、举报、管理员处理和审计日志；
- 推荐理由码、规则版本、曝光/点击/聊天/确认/履约埋点。

### 5.2 对象存储保存

- 第三方打车订单截图；
- 学生认证材料（如果 P1 开启材料上传）；
- 举报证据附件。

数据库只保存对象键、文件类型、大小、哈希、上传人、关联行程、访问权限、创建时间和删除/过期时间，不把大文件直接存入 PostgreSQL。

### 5.3 Redis（可选）保存

MVP 可以暂不引入 Redis；需要时用于：

- 登录/短信/接口限流；
- 短时验证码或一次性令牌；
- WebSocket 在线状态和未读计数缓存；
- 推荐列表短时缓存；
- 防重复提交和幂等锁。

Redis 不作为订单、费用、确认或审计记录的唯一数据源。

## 六、关键状态与事务边界

### 6.1 行程状态

```text
招募中
  → 双向确认中
  → 已成团
  → 待叫车
  → 已叫车
  → 行程结束待结算
  → 结算完成
  → 待评价
  → 已归档
```

成员申请与容量是独立于行程主状态的模型：拼友提交 1–2 席申请，发单人接受时后端以事务、行级锁和容量条件一次性校验全部席位；剩余不足则整笔失败，禁止部分接受。达到 3/4 人目标后停止接收新申请并进入“`双向确认中`”。`已满员`只是容量条件，不是终态。

15 秒反悔窗口内任一成员取消：

1. “撤回确认”使行程回退到“招募中”，当前确认记录全部作废，并释放全部非发单人活动成员席位；
2. “退出行程”只释放本人席位，并按取消规则记录；
3. 所有受影响成员收到站内通知；
4. 事务使用行级锁、版本号和幂等键，重复请求返回首次结果；
5. 保留操作日志，避免无法解释状态变化。

### 6.2 费用状态

```text
预估费用
  → 全部当前活动成员确认
  → 成团后锁定
  → 变更申请（如有）
  → 除申请人外的全部当前活动成员同意
  → 清空原确认
  → 重新全员确认
  → 再次锁定
  → 订单提交
  → 成员确认 / 订单有争议
  → 费用卡片 / 人工争议处理
```

以下操作必须由后端事务保证：

- 达到目标人数后，全部当前活动成员确认同时成立才创建成团关系；
- 成团后不能直接修改费用模式；
- 变更申请只有在除申请人外的全部当前活动成员同意时才生效；任一拒绝或 24 小时超时即失效，生效后旧确认必须整体失效；
- 订单提交后成员有 24 小时确认/异议窗口；异议或窗口超时均进入人工处理，不自动视为同意；争议期间结算、已付标记和互评必须同时锁定；
- 重复上传订单或重复点击确认不会创建重复记录。

## 七、外部服务适配器

### 7.1 短信与 Web 认证适配器

- 七牛云短信验证码发送；
- 验证码频率、失败次数和冻结策略；
- access/refresh Cookie 会话、刷新和撤销；
- 浏览器位置权限和 SOS 触发时的位置获取。

### 7.2 地图适配器

- 地点搜索和地理编码；
- 起终点距离/时间估算；
- P1 高德路线规划和路线重合计算；
- 地图服务不可用时允许手动输入地点或使用已保存地点。

### 7.3 第三方打车适配器

统一能力接口，不假设所有平台都支持同样能力：

```text
getSupportedCapabilities()
openRide(options)
copyRideDetails(options)
recordRideStarted(tripId, provider)
```

能力降级顺序：

1. 官方 Web/App 链接或合法带参唤起能力；
2. 合法带参跳转；
3. 复制起点、终点和时间；
4. 用户手动打开第三方 App；
5. 返回同路行确认“待叫车/已叫车”。

### 7.4 消息与短信适配器

- 七牛云短信用于登录验证码；
- SOS MVP 仅记录事件审计，并展示联系人/110 手动拨号引导；不写入通知 outbox，不自动发送短信/站外消息，不自动报警；
- 通知 outbox、送达状态和失败重试仅在未来通知供应商、签名模板、预算与隐私规则获单独批准后再作为 P1 接入。

## 八、安全、隐私与运维基线

- 所有客户端到后端通信使用 HTTPS/WSS；
- 数据库、Redis 和对象存储不直接暴露不受控公网入口；
- 订单截图仅允许 PNG/JPEG/WebP，单张不超过 10MB，使用短时授权 URL 或后端代理访问，不公开永久文件地址；结算完成后保留 90 天，有争议则处理完成后再保留 90 天；
- GPS 只在用户手动触发 SOS 时尝试获取；P0 不持久化精确 GPS，只记录位置获取结果和触发时间；
- 非成团状态展示模糊地点，不展示精确住址或持续轨迹；
- 后端所有状态变更记录操作人、时间、旧状态、新状态和原因；
- 对登录、手机号、SOS、订单上传、费用变更和确认接口做限流与幂等处理；
- VM、数据库、对象存储和日志均制定备份与保留周期；
- 管理员操作需要单独审计，普通用户不能访问管理员接口。

## 九、推荐的 MVP 进程部署

MVP 可以先采用单体后端，而不是微服务：

```text
同一个后端应用
├─ REST API
├─ WebSocket
├─ 定时任务
├─ 推荐/埋点模块
└─ 管理员 API
```

单体模块化更适合当前 3–4 人单车、单区域试点规模，减少部署和排障成本。未来只有在聊天、推荐、通知或管理后台出现独立扩展需求时，再拆分服务。

## 十、已确定与待确认清单

### 已确定

- Vue 3 + Vite + TypeScript + Vant + Pinia + PWA 客户端；
- 独立后端，不采用纯微信云开发作为核心业务后端；网站版由 Nginx 反代 Vue PWA 与 NestJS API；
- PostgreSQL；
- 七牛云 VM 承载后端；
- 第三方打车采用适配器和手动降级；
- 不做司机端、车辆实时定位、资金托管和自动行车守护；
- MVP 单车总人数 3 或 4（含发单人），一次加入 1–2 名拼友，按服务区域试点。

### 待确认

- PostgreSQL 生产环境采用托管服务还是 VM/独立持久化磁盘部署；
- Redis 是否在 MVP 接入（当前不接入，后续扩展 Socket.IO 多实例）；
- 七牛云 VM 的地域、规格、带宽、备份和监控套餐；
- 域名、HTTPS 证书和 ICP 备案（当前跳过，公网发布前必须补齐）；
- 目标首批用户量、并发量和服务区域数量。
