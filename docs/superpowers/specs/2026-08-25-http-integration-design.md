# Web 与 NestJS 真实 HTTP 联调设计

## 目标

让主要 Web/PWA 页面在 `VITE_API_MODE=http` 下使用真实 NestJS API 完成行程、我的出行、聊天、车辆/叫车、费用和评价闭环；保留 Mock 客户端作为测试替身，不把开发认证占位误认为生产认证。

## 范围

- 后端新增 `GET /trips/mine?role=joined|published`，只返回当前用户可见的行程摘要。
- 统一前后端行程状态和确认响应字段，修复成员数从 `members[].memberCount` 汇总的问题。
- Web API 契约增加我的行程、费用确认/异议、车辆保存、叫车降级和消息游标分页。
- `MyTripsView`、`OrderView`、`RideView`、`ChatView`、`ReviewView` 改用真实 API，补齐加载、空状态、错误、重试和成功反馈。
- 个人页紧急联系人保存改为真实 API；不实现自动短信、自动报警或精确位置存储。
- 当前 HTTP 联调继续使用开发登录与 `x-user-id`；真实短信/会话认证作为后续独立任务，页面必须显示其开发边界，不得用于生产。

## 数据流与契约

1. Web API 客户端统一添加 `Idempotency-Key` 到所有写请求，保留 `credentials: include`。
2. 后端响应中的 `departTime`、`reasonCodes`、确认信息、订单状态由 Adapter 归一化为前端字段。
3. 我的行程接口按 `role` 查询创建者或成员关系，禁止返回无关用户的行程。
4. 费用创建暂不伪造上传成功；Kodo 签名未接入前，订单页只处理已有订单的确认和异议。
5. 聊天 API 保留后端的 `before`/`limit` 游标语义，页面以时间正序展示并支持加载更早消息。

## 页面行为

- 我的出行：真实查询、分为发布/加入两个标签，支持空列表和重试。
- 订单：加载失败可重试；争议后锁定确认和评价；确认/异议成功后刷新详情。
- 车辆与叫车：保存车辆调用后端；叫车不可用时展示复制路线和手动拨号降级，不出现硬编码行程或手机号。
- 聊天：拒绝纯空格消息；发送失败保留输入；分页失败可重试。
- 评价：从行程成员中选择目标用户，排除当前用户，不再要求手填 ID。
- 紧急联系人：保存姓名和手机号到后端，明确仅保存联系人和通知意图。

## 验证策略

- 先为新增契约和页面行为写失败测试，再实现最小代码。
- API：单元测试、Nest 构建、真实 PostgreSQL HTTP E2E。
- Web：Vitest、TypeScript 检查、生产构建/PWA 资源检查。
- 验收禁止依赖静态 `trip-1`、硬编码路线或电话号码；未接入真实认证、Kodo、WebSocket 的边界必须在文档中保留。
